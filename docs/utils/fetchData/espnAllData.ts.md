# File: `backend/src/utils/fetchData/espnAllData.ts`

## Purpose

Fetches teams and per-team schedules from ESPN APIs, normalizes them into game payloads, and exposes score helpers. Used by `GameService.getLeagueGames()` (normal + oldies paths) via `getTeamsSchedule()`.

## Key Features

- **Two fetch paths in `getEachTeamSchedule()`**:
  - **Scoreboard path** (Olympics + soccer `MLS`/`NWSL` only): `GET {sport}/{league}/scoreboard?dates={year}&limit=1000&page={n}`, filtered per team by `competitors.team.id`. Years = `[season]` when `season` is given (oldies), else `getCurrentSeasonYears(leagueName)`.
  - **Team schedule path** (all other leagues, **including the 6 college leagues** `NCAAF, NCAAB, NCCABB, WNCAAB, NCAAMH, NCAAWH`): `GET teams/{id}/schedule?seasontype={1,2,3}[&season={season}]`. `fetchESPNTeamScheduleEvents()` requests up to 1,000 events per page, follows ESPN's next-page link/metadata and checks a full 1,000-event response for a further page. It deduplicates overlaps and fails explicitly if ESPN advertises another page but pagination makes no progress. With `season` (oldies) all fetched games are kept; without it, games older than `untilDate` (10 months when `forceUpdate`, else now) are dropped. ESPN currently often returns team schedules in one response without page metadata; in that case one response is used unless the page is full.
- **Schedule progress logs** — each team logs the number of fetched games, followed by a league summary with team schedule and distinct-match counts. The service logs a final persisted/upserted count after refresh cleanup.
- **Olympic historical team discovery** (`getOlympicSeasonTeams(league, season)`): before an Olympic oldies fetch, scans that season's scoreboard for each sport in the aggregate league and returns every participant, not just countries in the current database roster. Newly found teams are stored inactive with their provider IDs and added to that recovery's schedule crawl. Aggregate schedule traversal routes each team only to its own sport.
- **Olympic country flag fallback** (`getOlympicTeamLogo(league, abbrev)`): when ESPN omits a country's logo, resolves its three-letter country code to ESPN's country-flag image URL. Strips the optional `-M`/`-W` suffix and works for both men's and women's leagues. This is applied during roster discovery, historical scoreboard discovery, and game normalization so every event has a fallback even when no current team roster supplies a logo. ESPN's optional singular `team.logo` is modeled alongside `team.logos[]` and both are checked before the fallback.
- **ESPN team logo selection** (`getESPNTeamLogo(team, preferredRelations?)`): keeps the existing `logos[2]`, `logos[0]`, and singular `team.logo` preference order, then checks available logos by ESPN's `rel` labels (`default`, `full`, `scoreboard`, and primary-logo variants), and finally any remaining non-empty `href`. Scoreboard game normalization can prioritize the `full` + `scoreboard` variant. Only after these ESPN options are exhausted does the caller use the local university map or Olympic flag fallback.
- **Olympic basketball scoreboard slugs** (`leagueConfigs`): the valid ESPN league slugs are `mens-olympics-basketball` / `womens-olympics-basketball` (sport `basketball`). The word order matters — the earlier `olympics-mens-basketball` / `olympics-womens-basketball` were answered with **400 Bad Request** ("Failed to get events endpoint"), so the entire Olympic basketball oldies crawl silently returned nothing. The Olympic hockey slugs (`olympics-mens-ice-hockey` / `olympics-womens-ice-hockey`) are correct as-is.
- **College leagues use the team schedule endpoint** (not scoreboard): the `scoreboard?dates={year}` path does not return their full history.
- **Team discovery** (`getESPNTeams`): `GET teams?limit=1000` (the `limit` is mandatory — without it ESPN paginates and returns only ~50 teams, silently hiding most of the roster, e.g. NCAAB Akron). College leagues then add-only enrich by scanning up to **10 scoreboard pages** (`limit=1000`, early stop when a page returns < 1000 events) of the **current year** for `CollegeLeague`. Teams without an `isActive` flag (scoreboard-only partial objects) are accepted so the enrichment is not filtered back out. Logs `[Teams] <LEAGUE>: +N extra teams discovered via scoreboard pages.`
- **University logo resolution** (`resolveUniversityLogo(league, abbrev)`): league-scoped key `'{LEAGUE}-{ABBREV}'` first (logo may differ per sport), systematic fallback to plain `'{ABBREV}'`. Used in team mapping, match payloads, `getTeamsLogo()`, and the pre-save fallback in `TeamService.getTeams()`.
- **Division-1-only college schedules** (`getD1ScheduleTeamIds()`, `isD1ScheduleTeam()`) recheck every stored team before requesting schedules, rather than trusting a stale database roster. The check uses ESPN group parents where reliable — football FBS+FCS `80/81`, basketball `50`, baseball `27` — plus the explicit **`NCAAMH_D1_TEAMS`** (64 programs) and **`NCAAWH_D1_TEAM_IDS`** (41 programs) allowlists, because ESPN does not distinguish D1 from lower divisions in either college hockey league. A team ESPN's detail endpoint **cannot** verify (it answers 404 for ids it does not know — small D3 opponents or programs too recent for the endpoint — or a transient fetch failure / group-less payload) is cross-checked against the league's full roster (`teams?limit=1000`, also carrying `groups`; cached six hours, failed fetches retried after 60s): found there, the roster's groups decide; absent from a **successfully fetched** roster the team is treated as non-D1 and its schedule is not requested; only when even the roster is unreachable (network outage) is the team kept fail-open with a warning and no cached verdict (`[Schedule] … and the league roster was unavailable; assuming Division I (fail-open)…`). One unverifiable team never aborts the whole league refresh. An **incomplete schedule payload** (missing/invalid `events`) still fails the league refresh explicitly instead of saving a partial schedule as complete.
- **Per-game Division 1 rule** — every fetched college game is checked on both sides and is **kept as soon as ONE participant is Division 1**: a D1 program's fixture against a lower division (D2/D3) belongs to its schedule and is inserted in the database. Only a game between two teams that are **both** provably non-D1 is excluded. An opponent not in the local roster is verified directly with ESPN (three-step degradation: detail endpoint → league roster → fail-open), so a missing local D1 team is never wrongly discarded and one unknown opponent never aborts the league refresh. This rule is a safety net: the pre-filter above already only requests schedules for D1 teams, so a non-D1-vs-non-D1 fixture only reaches it when a team had to be kept fail-open. Verified divisions are cached for six hours.
  - **It applies to both fetch paths**: the check runs after the date cutoff and does not depend on `season`, so the live/forced refresh (`getLeagueGames()`) and the historical recovery (`getLeagueGames({ season })`, `addMissingOnly`) behave identically — a past D1-vs-D3 fixture is recovered just like an upcoming one. With `season`, the date window is bypassed entirely (the season's full schedule is fetched), so the per-game rule is the only division filter in play there.
- **Hockey leagues keep every game** (`UNVERIFIABLE_DIVISION_LEAGUES` = `NCAAMH`, `NCAAWH`): ESPN reports the same group parent for D1, D3 and non-NCAA (U Sports) programs, so a per-game division verdict would be a guess. The per-game filter is skipped entirely for these leagues and **every fetched game is kept**, including a fixture against an opponent the allowlist does not know. The allowlists still decide which teams have a schedule requested, so only known D1 hockey programs are followed.
- **D1 schedule exclusion diagnostics** — after a college league refresh, excluded events (games where no participant is verified as D1) are deduplicated by ESPN event ID and summarized once per league with the distinct event count, affected team-schedule count, and up to ten non-D1/unverified opponent names and provider IDs (plus counts). Events with missing or malformed competitor data are skipped and logged separately, not counted as non-D1 exclusions. The per-team fetched-game logs and league distinct-game completion summary remain intact.
- **Division-1-only roster imports** (`getESPNTeams()`): ESPN groups filter other college teams at import. For leagues with a provider division marker, a detail-fetch failure remains fail-open during discovery so a transient outage does not erase a team; schedule crawling re-verifies each team's division the same three-step way — only positive proof of non-D1 (from the detail endpoint or the league roster) drops a team or excludes a game. Hockey exceptions use the allowlists above.
- **University logo backfill** (`TeamService.backfillMissingUniversityLogos()`): runs ONLY at the end of `getTeams()` — i.e. manual `POST /teams/refresh?leagueParam=` or the monthly `updateTeams` cron, never on game fetches. Missing/empty logo keys are filled with the working `teamLogo` under BOTH scoped and plain keys.
- **University team colors** (`getTeamColors(uniqueId)` from `../Colors`): when ESPN returns no `color`/`alternateColor`, the colors of the same university abbreviation in another college league are used (`NCAAB-X` → `NCAAF-X` / `NCAAMH-X` …) instead of the generic `#ffffff` on `#000000` placeholder. Non-college leagues keep the default placeholder.
- **Leagues with no ESPN schedule config are skipped, not crashed on**: `getEachTeamSchedule()` bails out with `[]` (and a `No ESPN schedule config for league "<X>"` error log) when `leaguesData[leagueName]` is missing — `leaguesData` is derived from `leagueConfigs`, so it has no entry for the PWHL (served by `hockeyData.ts`) or for an unknown name. Its `catch` also returns `[]` instead of `undefined`, which both callers (`[...allGames, ...games]` in the aggregate-league recursion, and the `allGames[leagueID]` store) require.
- **Resilience**: 15s fetch timeout (`fetchWithTimeout`) + 1 network retry (`fetchWithRetry`) + graceful degradation via `fetchJsonOrNull()` (fails open on rate-limit / HTML responses, e.g. ESPN bot-block or team-not-found pages). Every ESPN request carries a browser-like `User-Agent` + `Accept` (`ESPN_DEFAULT_HEADERS`) so Akamai does not treat it as a bot.
- **Graceful degradation** (`fetchJsonOrNull()`): never parses JSON from a non-JSON body. Non-2xx or non-JSON responses (ESPN rate-limit / bot-block / team-not-found) return `null`, so the league still refreshes for the other teams instead of aborting the run. **`403` and `429` are treated as transient** (ESPN's Akamai edge answers request bursts — e.g. the oldies crawl firing hundreds of `teams/{id}/schedule` calls back-to-back — with an HTML "Access Denied" 403 page that is a soft rate-limit, not a real "not found"): both are retried up to `ESPN_MAX_RETRIES` (2) times with exponential backoff, honouring the `Retry-After` header when present, before falling back to the safe path. A genuine non-retryable status (e.g. `404`) fails open immediately. The `[ESPN] Skipping …` warning is **throttled**: the first skip is logged in full, then only every `ESPN_SKIP_LOG_EVERY` (25th), so a large blocked crawl no longer floods the console with one line per team.
- **Crawl pacing** (`getTeamsSchedule()`): a small gap (`ESPN_TEAM_BATCH_DELAY_MS`, 120 ms) is inserted between the concurrency-2 team batches to keep the request rate under Akamai's threshold and avoid triggering the transient 403 blocks in the first place.
- **Score helpers**: `getESPNScores()`, `getESPNGameScore()`, `getTeamsSchedule()`.
- **Game status normalization (`resolveScheduleGameStatus(status)`)**: maps an ESPN `STATUS_*` name to
  the value stored in `game.gameStatus`, by **family** and not by equality:
  `FINAL*` / `FULL_TIME*` → `FINISHED` (so `STATUS_FINAL_AET`, `STATUS_FINAL_PEN`,
  `STATUS_FINAL_OT`, `STATUS_FULL_TIME_2` are all final), `POSTPONED*` → `POSTPONED`,
  `CANCELLED*`/`CANCELED*` → `CANCELLED`, `DELAYED*`/`SUSPENDED*`/`INTERRUPTED*` → `DELAYED`,
  `IN_PROGRESS*` → `IN_PROGRESS`, any other `STATUS_*` → a readable value (`STATUS_HALFTIME` →
  `"HALFTIME"`), no status → `null`. Case insensitive.
  The previous equality whitelist only knew `STATUS_FINAL` / `STATUS_FULL_TIME` / `STATUS_POSTPONED`
  / `STATUS_CANCELLED`; every suffixed final status fell through to the generic `STATUS_*` branch
  and was stored as `"FINAL AET"`. No terminal-state check recognized that value, so
  `GameService.removeStaleUnresolvedGames()` classified a fully played game (e.g. MLS
  `MLS-SEA-557514`, final 4-3 after extra time) as "unresolved" and deleted it.
- **Team records (`homeTeamRecord` / `awayTeamRecord`)**:
  - `extractCompetitorRecord(competitor)` — the single reader for both ESPN shapes: the singular `competitor.record` array (`displayValue`) returned by `teams/{id}/schedule`, and the plural `competitor.records` array (`summary`) returned by `scoreboard` / `summary`. Entry priority is `total` → `ytd` → first entry, because the NHL/season schedules only expose `ytd` while the post-season schedule and the scoreboard expose `total`. The previous `records.find(r => r.type === 'total')` lookup therefore returned `''` for the NHL scoreboard and for `getESPNGameScore()`. The trailing `", 109 PTS"` hockey suffix is stripped, so a bare `"W-L-T"` string is stored.
  - `getEachTeamSchedule()` writes a **cumulative** tally (record at the time of the game) on the team-schedule path — that path previously wrote no record at all, which is why past seasons had none.
  - Each event retains its ESPN `seasonType` (1 = preseason, 2 = regular season, 3 = playoffs) while records are normalized. Scoreboard events use their season metadata; team-schedule events retain the exact `seasontype` request that returned them.
  - `applySeasonFinalRecords(allGames)` groups records by phase, so preseason, regular season, and playoffs cannot contaminate one another. **Upcoming** games (start time in the future) have their per-game record **cleared** (`''`) so the reader (`GameService._enrichGameWithTeamData()`) falls back to `team.record` — the team's current tally stored in the database, kept up to date by `syncGameWithScore()` and the records cron. A game that has not started has no meaningful pre-game tally, so the current DB record is shown instead of the placeholder `0-0-0`. A phase that has not started **and is already in the past** still shows `0-0-0`. Already-played games retain their game-specific records.
  - Once preseason or regular season is over, each game in that phase receives the verified final tally, preserving the existing end-of-season historical display. Playoff records remain attached to individual games instead of being replaced with the final tally on every game. Series headlines/statuses remain in separate `seriesSummary` / `seriesStatus` fields and are not copied into the team records.
  - **Truncated phases are detected** (`getSeasonFinals()`, shared with `GameService._backfillSeasonRecords()`): a team's tally implying **more** games than were fetched for that team proves the phase batch is incomplete (ESPN quota exhausted, pagination cut short, or a team fetch that failed). Such a tally is not treated as a phase final, and a `[ESPN] Season type N looks truncated for N team(s) (…)` warning is logged. Games are de-duplicated per team by game identity, so the two rows a match produces (one per `teamSelectedId`) never inflate the count.

## Data Flow

1. `getTeamsSchedule(leagueName, ...)` fans out per team (concurrency 2) to `getEachTeamSchedule()`.
2. `getEachTeamSchedule()` picks scoreboard vs team-schedule path, fetches, then maps events to normalized game objects (including a cumulative `homeTeamRecord` / `awayTeamRecord`), using the exported `fetchJsonOrNull()` helper.
3. `applySeasonFinalRecords()` normalizes those records across the whole league batch: final tally for a finished season, cleared record for upcoming games (so `_enrichGameWithTeamData()` shows the DB `team.record`), and game-specific records for games already played.
